### 4.3 C 组：匀色方法耗时（2024 四景）

| 方法 | 输出形态 | 耗时 |
|---|---|---|
| `overlap_adjust`（默认，图平差） | VRT（零像素落盘） | **6.6s** |
| `global_adjust` | VRT | **6.2s** |
| `block_wallis` | 物理 GeoTIFF ×4 | **179.0s** |
| `hist_match` | 物理 GeoTIFF ×4 | **201.3s** |

**结论**：耗时差异来自**输出形态**而非算法本身——VRT 模式零像素落盘（仅统计），物理模式需写出 4 景 DEFLATE 压缩 GeoTIFF，**相差约 30×**。生产默认 `output_mode=vrt` 的选型由此得到数据支撑。

## 五、性能测试

### 5.1 服务化并发与内存（7 场景 / 13 任务，详见《Phase4压测报告.md》）

| 场景 | worker×线程 | 规模 | 总耗时 | 峰值 RSS | health 失败 |
|---|---|---|---|---|---|
| s1 | 1×4 | 4 任务（匀色为主） | 118.2s | 680MB | 0 |
| s2 | 2×4 | 同上 | 62.6s（**1.89×**） | 680MB | 0 |

## 七、代码审计发现与修复（本轮）

对 core / operators / apps / 构建 / 文档做三路独立只读审查，共 26 项发现。**高严重度 5 项全部修复**：

| 严重度 | 问题 | 根因 | 修复 |
|---|---|---|---|
| 高 | `log.cpp` 栈越界读 | `snprintf` 返回"应写长度"（可 >缓冲），却按该长度 `fwrite` | 夹取为 `min(n, sizeof-1)` 后再写 |
| 高 | `nodata_pct_threshold` 语义与文档相反 | 实现比较**有效**占比，文档与参数名是**无效**占比（仅阈值=50 时巧合等价） | 改为 `invalidRatio >= threshold`；B09 用例锁定 |
| 高 | `--max-zoom 0`（CGCS2000）触发负层级索引 | `maxZ = max_zoom - idOffset` 未做下界夹取 → `tms_.level(-1)` UB | 夹取到 `[0, levelCount-1]` |
| 高 | 信号屏蔽晚于线程创建 → 优雅退出可能失效 | `mgr.start()` 建线程后才 `pthread_sigmask`，新线程继承未屏蔽掩码 | 屏蔽提前到 `main` 最先执行 |
| 高 | 关机可能永久挂起 | reaper 仅在无运行任务时返回，`stop()` 只发 SIGTERM 无升级 | 限时等待后升级 SIGKILL |
| 中 | Wallis 目标优先级与文档相反 | `wallis_target_std` 无条件覆盖显式 `target_std` | 仅当 `target_std` 未指定时生效 |
| 中 | Wallis 块统计忽略 RGB nodata | 仅判 alpha，与其它路径口径不一致（暗景无效区 0 值拉偏统计） | 统一 nodata 掩码 |
| 中 | 镶嵌 COG 分支句柄泄漏 | `openReadOnly().release()` 后早退未关闭 | 改用 `DataSetPtr` |
| 中 | workflow 未判工厂返回空指针 | 与 color_balance_main 不一致 | 补判空 |
| 中 | 取消语义误导 | running 仅发信号却立即回 200 canceled | 改 202 `cancel_requested` |
| 中 | 任务表无界增长 / 列表全量返回 | 无淘汰与分页 | 内存表上限 2000（终态最旧驱逐，磁盘保留）+ 列表上限 200 |
| 中 | `bbox` 校验时机不一致 | 执行期才校验（退出码 1） | 移入 `configure()`（退出码 2） |
| 中 | `vrt_writer` 波段 >4 越界 | ColorInterp 名表固定 4 项而按 nb 索引 | 越界时用 `Undefined` |
| 低×12 | 死代码与冗余 | — | 删除 `resampleToTile`/`clamp255`（无调用）、`RenderCtx` 未用字段（`params`/`levelRes`/`resumed`/`tileW`/`tileH`）、`Scene::paramsSet`、`OverlapEdge` 交集窗口 8 字段、`graph_ls` 未用 `eps`、`gdal_raii` 未用 `resX/resY`、`logFilePath()` API；移除**空转参数** `tiles_scope`（语义已由 `bbox` 承载）；`vcpkg.json` 补声明 `gtest`；Bearer 改为常量时间比较 |

**未修复但已记录**（评估后接受或属设计取舍）：`block_stats` 三处 hist→mean/std 计算重复、`append` 重叠统计两轮循环 —— 属可读性重复，重构收益低于改动风险，已在代码注释与本文件记录；`writeAtomic` 无 `fsync`（掉电尾部可能不完整）。

## 十、已知限制

- 硬件固定 4 核 / 9.7GB，容量结论的量级可外推、绝对数值不可。
- 压测未覆盖 worker > 2、多机分布式、万级瓦片长任务、磁盘 I/O 竞争、混合负载并发。
- 服务化任务 JSON 中的输入/输出路径未做白名单约束（默认无 token 部署时建议置于反向代理与受限文件系统之后，见 §六 R11 与《服务化使用说明.md》）。
- `z14 diff=3.54`（bilinear vs GDAL CLI near）有产物但未复算数值；GF2 skip 15898 的原始日志已被后台任务截断。
