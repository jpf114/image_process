## 二、Phase 4 服务化设计（方案 §4.5 细化）

> **前置论证见 [Phase4服务化论证报告.md](Phase4服务化论证报告.md)**（2026-10-13）：cpp-httplib + 1 调度进程 + N worker(fork/exec) 判定为可行且成熟（Gunicorn sync worker 同范式），须落实 8 项工程约束——尤其 ①长任务不得占用 HTTP 线程 ②GDAL 官方禁止叉在 GDAL 操作中途，worker 必须 fork+exec ③容器内显式指定线程数（cgroup CPU 探测失真）④内存决定 worker 并发上限；无需 Redis/Celery（内存队列 + 磁盘 JSON 原子写即可）。

### 2.1 架构
```
┌────────────┐   HTTP    ┌──────────────────┐  fork/exec  ┌─────────────┐
│ 客户端      │ ────────▶ │ ip_server (cpp-  │ ──────────▶ │ worker 进程  │
│ (提交/轮询) │ ◀──────── │ httplib, 薄层)    │  任务JSON    │ (workflow/  │
└────────────┘  状态/结果 │  - 任务队列(内存) │             │  单 operator)│
                          │  - worker 池管理  │ ◀────────── │  独立崩溃隔离│
                          │  - 静态瓦片预览   │  状态回写     └─────────────┘
                          └──────────────────┘
```
- **进程模型**：1 调度进程 + N worker（默认 = 内存允许的并发数，遵守 MemGuard）；worker 崩溃不影响服务（多进程隔离动机落地）
- **任务**：JSON（与 workflow 配置同构）→ 队列 → worker 执行 → 状态机（queued/running/done/failed）+ 进度百分比（operator ProgressCallback 已具备）
- **接口**（REST，v1）：
  - `POST /api/v1/jobs`（提交，返回 job_id）
  - `GET /api/v1/jobs/{id}`（状态/进度/日志尾部）
  - `GET /api/v1/jobs/{id}/logs`（运行日志——**日志落盘能力已具备**）
  - `DELETE /api/v1/jobs/{id}`（取消）
  - `GET /tiles/...`（静态瓦片服务，映射输出目录）
- **依赖**：cpp-httplib（header-only，vcpkg 有，**加装需征得同意**）；无 DB（任务队列内存 + 磁盘 JSON 状态文件，重启可恢复）
- **Docker**：debian-slim 基础镜像 + dist 包（package_release.sh 产物）+ EXPOSE；无 GUI/驱动依赖，纯 CPU 友好（方案 §4.5 已确认）

## 三、MBTiles/GPKG 打包（调研要点，Phase 4 后按需）

- **MBTiles**：SQLite 单文件（tiles 表 z/x/y blob）；GDAL 有 MBTiles 驱动（Create 支持 raster）——可直接 CreateCopy 或逐瓦片 INSERT；优点：单文件分发；缺点：更新需重写
- **GPKG**：OGC 标准，GDAL GPKG 驱动（raster/tile table）；优点：标准+多层级；推荐作为默认打包目标
- 实现：tiling 加 `package=mbtiles|gpkg` 参数，渲染管线复用（编码后写包而非文件）；**增量追加**（新影像 → INSERT OR REPLACE 受影响瓦片）与断点续跑语义一致
- 工作量：3~4 天（含增量语义与测试）

## 四、GPU 路线（有 NVIDIA GPU 环境后）

- 现状：本期纯 CPU 已确认（决策 4）；接口占位（use_gpu）
- 候选：OpenCV CUDA（calcHist/LUT，vcpkg opencv4[cuda] feature）、CV-CUDA、cuCIM
- 收益评估先行：匀色=统计+逐像素 LUT，属带宽型；瓦片编码为瓶颈时 GPU 无收益——**先用 nsight/perf 定位热点再决定**，避免盲目 GPU 化
- 工作量：编译开关 + 统计/LUT 两条路径 + A/B 基准（约 1 周，需 GPU 环境）
