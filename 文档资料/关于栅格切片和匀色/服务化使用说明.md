# 服务化使用说明（ip_server，Phase 4）

> 设计论证见《Phase4服务化论证报告.md》；架构：**1 个调度进程（HTTP 控制面）+ N 个 worker 子进程（fork/exec → workflow exe）**。

## 1. 启动

```bash
export LD_LIBRARY_PATH=$HOME/vcpkg/installed/x64-linux/lib:$LD_LIBRARY_PATH
export GDAL_DATA=$HOME/vcpkg/installed/x64-linux/share/gdal
export PROJ_DATA=$HOME/vcpkg/installed/x64-linux/share/proj

bin/Release/ip_server \
  --data-dir  ipdata \          # 任务状态与日志根（必需）
  --tiles-dir out/tiles \       # 静态瓦片根（可选，映射 /tiles/）
  --port 8080 \
  --workers 1 \                 # worker 并发上限（默认 min(核数, 内存/3GB)）
  --min-mem-gb 1.5 \            # 派发前内存守卫
  --token <可选 Bearer 令牌>
# 也可 --worker <路径> 指定执行体（默认取自身同目录的 workflow）
```

启动日志会打印：监听地址、数据目录、执行体、worker 并发上限。

## 2. REST 端点（v1）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/health` | 健康检查（免鉴权，供容器探针） |
| POST | `/api/v1/jobs` | 提交任务，body = **workflow 同构 JSON**（可选 `name` / `only`） |
| GET | `/api/v1/jobs` | 任务列表（id/name/state/percent） |
| GET | `/api/v1/jobs/{id}` | 状态/进度/退出码/消息 |
| GET | `/api/v1/jobs/{id}/logs` | 运行日志尾部（stdout + stderr） |
| DELETE | `/api/v1/jobs/{id}` | 取消（queued 直接置 canceled；running 发 SIGTERM） |
| GET | `/tiles/...` | 静态瓦片（映射 `--tiles-dir`） |

状态机：`queued → running → done | failed | canceled`。若 `--token` 非空，除 `/api/v1/health` 外均需 `Authorization: Bearer <token>`。

## 3. 提交任务（示例）

```bash
curl -X POST -H 'Content-Type: application/json' \
  --data-binary @job.json http://127.0.0.1:8080/api/v1/jobs
# → {"job_id":"20261013_115932_2","state":"queued"}

curl http://127.0.0.1:8080/api/v1/jobs/20261013_115932_2      # 状态/进度
curl http://127.0.0.1:8080/api/v1/jobs/20261013_115932_2/logs # 日志
curl http://127.0.0.1:8080/tiles/13/6492/1387.png             # 取瓦片
curl -X DELETE http://127.0.0.1:8080/api/v1/jobs/<id>         # 取消
```

`job.json` = 与 `workflow --config` 完全同构（见 AGENT.md §7），另可带：

```json
{
  "name": "2024 匀色切片",
  "only": "",                        // "" 全流程 | "color" | "tiling"
  "color_balance": { "...": "..." },
  "tiling": { "...": "..." }
}
```

> 注意：`tiling.input` 留空时自动接匀色镶嵌 VRT（`<color.output_dir>/mosaic.vrt`）；因此**匀色需选会产出 mosaic.vrt 的模式**（`profile_mode=create`/`append`；`apply` 为逐景应用、不生成镶嵌 VRT，请勿直接接切片）。

## 4. 运行语义（按论证报告 §7 落实）

| 项 | 行为 |
|---|---|
| 控制面/执行面分离 | 长任务不占用 HTTP 工作线程；提交立即返回 job_id |
| worker 启动 | `posix_spawn` + exec（全新镜像），规避"GDAL 操作中途 fork"的锁残留问题 |
| 并发上限 | `--workers`；默认 `min(物理核数, 可用内存/3GB)` |
| 内存守卫 | 派发前检查 `MemGuard`，可用内存低于 `--min-mem-gb` 时任务保持排队 |
| 崩溃隔离 | worker 被 kill/崩溃 → 该任务 `failed`（退出码 128+sig），服务不受影响，队列继续 |
| 取消 | running → SIGTERM（独立进程组）；确认后置 `canceled` |
| 优雅退出 | SIGTERM → 停止接收、SIGTERM 全部 worker、等待回收（容器内由 tini 转发） |
| 状态持久化 | 每任务 `<data-dir>/jobs/<id>/state.json`（原子写：临时文件 + rename） |
| 重启恢复 | 启动加载历史；上个生命周期中 `running` 的任务标记 `failed / 服务重启中断`（可重提交，切片支持断点续跑） |
| 进度 | 解析 worker stdout 日志的 `[NN%]`（operator 既有格式），非阻塞 |

## 5. 目录结构

```
<data-dir>/jobs/<job_id>/
├── task.json      # 提交时的 workflow 配置
├── state.json     # 状态/进度/退出码（原子写）
├── stdout.log     # worker 标准输出（含 operator 进度）
└── stderr.log     # worker 标准错误
```

## 6. 容器化

见 [docker/Dockerfile](file:///home/tdt-dell/code/MyProject/image_process/docker/Dockerfile)：**ubuntu:24.04** + 交付包 + tini + tzdata；`GDAL_NUM_THREADS` 显式设定；`/data`、`/tiles` 走卷。

```bash
scripts/package_release.sh
mkdir -p docker/ctx && tar xzf dist/image_process.tar.gz -C docker/ctx
docker build -f docker/Dockerfile -t image-process:0.1 docker/ctx
docker run --rm -p 8080:8080 --cpus 4 --memory 8g \
  -v "$PWD/ipdata:/data" -v "$PWD/tiles:/tiles" \
  -v "$PWD/文档资料/关于栅格切片和匀色/data:/data_src:ro" \
  image-process:0.1
```

**三条实测约束（务必遵守）**：

1. **基础镜像必须不旧于构建机**：本项目在 Ubuntu 24.04（glibc 2.39）构建，二进制依赖 `GLIBC_2.38`/`GLIBCXX_3.4.32`；用 `debian:12-slim`（glibc 2.36）会报 `version 'GLIBC_2.38' not found` 而无法启动。默认基础镜像为 `ubuntu:24.04`，可用 `--build-arg BASE=<tag>` 覆盖。
2. **无 docker.io 访问时**用本地已有 tag 构建（如 `--build-arg BASE=debian:bookworm-slim`，但须满足第 1 条 glibc 要求）。
3. **`TZ=Asia/Shanghai` 需 `tzdata`**：镜像已安装 tzdata（否则日志时间戳为 UTC）。

**已验证（2026-10-13 实测）**：镜像 263MB；容器内提交任务 → 进度 12%→85%→100% → done（9.5s，写出 1 瓦片）→ 宿主卷可见瓦片 → `GET /tiles/…` 返回 200/30837B；`docker stop` 由 tini 转发 SIGTERM，ip_server 打印"收到信号 15，开始优雅退出"并干净退出。

> 不同 CPU 配额的主机请覆盖 `GDAL_NUM_THREADS`（默认 4）并在任务 JSON 中显式设置 `tiling.num_threads`。
